# .NET 中加载 JSON 配置
在 .NET 生态系统中，加载 $\text{JSON}$ 配置主要通过 `Microsoft.Extensions.Configuration` 命名空间下的组件来实现。
加载 JSON 配置文件主要有两种方式：**手动方式 (传统) 和 自动方式 (Host/现代)**。

| **方式**      | **核心组件**                      | **目的**               | **优点**                                           | **缺点**                   |
| ----------- | ----------------------------- | -------------------- | ------------------------------------------------ | ------------------------ |
| **A. 手动加载** | `ConfigurationBuilder`        | 独立构建配置对象，不依赖于 Host。  | 独立、灵活，可加载任意文件。                                   | 容易忘记加载环境变量/命令行，不自动集成 DI。 |
| **B. 自动加载** | `Host.CreateDefaultBuilder()` | 由 Host 统一管理配置的加载和合并。 | **自动、简洁**，包含了所有默认配置源（环境变量、JSON、命令行），**自动集成 DI**。 | 必须使用 `IHost` 启动整个应用程序。   |
## 手动加载（使用 ConfigurationBuilder）
这是最常见的方式，适用于任何 .NET 应用程序（比如控制台应用程序、Web 应用等）。`ConfigurationBuilder` 用于将多个配置源加载到一个 `IConfigurationRoot` 中。可以通过配置文件（如 `appsettings.json`）来加载和读取应用程序的设置。
它让您对加载的文件路径和顺序有完全的控制权。
```csharp
// 1. 创建 ConfigurationBuilder 实例
var builder = new ConfigurationBuilder()
    .SetBasePath(AppContext.BaseDirectory); // 设置配置文件搜索的基础路径

// 2. 添加 JSON 文件作为配置源
builder.AddJsonFile("appsettings.json", optional: true, reloadOnChange: true);

// 3. 添加特定环境的 JSON 文件
string environment = Environment.GetEnvironmentVariable("DOTNET_ENVIRONMENT") ?? "Production";
builder.AddJsonFile($"appsettings.{environment}.json", optional: true, reloadOnChange: true);

// 4. 构建 IConfiguration 实例
IConfiguration config = builder.Build();
```
通过这种方式获得的 `config` 对象是一个独立的配置树，**不依赖于 DI 容器**。您可以直接使用它来读取值。
## 自动加载（使用 IHost）
这是现代 .NET 应用程序（ASP.NET Core, Worker Service, WPF/WinForms 推荐）的默认方式。
```csharp
IHost host = Host.CreateDefaultBuilder(args)
    // 自动执行了方式 A 中的所有配置加载步骤
    // 并添加了环境变量、用户机密等系统配置源
    .Build();

// Host.Services 内部的 IConfiguration 已经包含了加载的内容
IConfiguration config = host.Services.GetRequiredService<IConfiguration>();
```
Host 自动加载的配置源顺序： (后加载的会覆盖先加载的)
appsettings.json
appsettings.{Environment}.json
秘密管理器 (User Secrets)
环境变量 (Environment Variables)
命令行参数 (Command-line arguments)

## **`IConfiguration`（接口）**
- `IConfiguration` 是配置系统的主要接口。它定义了如何访问配置信息。你可以通过它读取配置文件（如 `appsettings.json`）、环境变量、命令行参数等数据源中的配置项。    
- `IConfiguration` 是对外提供的主要接口，其他组件（如 `IOptions<T>` 和 `ConfigurationBuilder`）都依赖于它来获取和操作配置。
```csharp
using System.Collections.Generic;
using Microsoft.Extensions.Primitives;

namespace Microsoft.Extensions.Configuration
{
    /// <summary>
    /// Represents a set of key/value application configuration properties.
    /// </summary>
    public interface IConfiguration
    {
        /// <summary>
        /// Gets or sets a configuration value.
        /// </summary>
        /// <param name="key">The configuration key.</param>
        /// <returns>The configuration value.</returns>
        string? this[string key] { get; set; }

        /// <summary>
        /// Gets a configuration sub-section with the specified key.
        /// </summary>
        /// <param name="key">The key of the configuration section.</param>
        /// <returns>The <see cref="IConfigurationSection"/>.</returns>
        /// <remarks>
        ///     This method will never return <c>null</c>. If no matching sub-section is found with the specified key,
        ///     an empty <see cref="IConfigurationSection"/> will be returned.
        /// </remarks>
        IConfigurationSection GetSection(string key);

        /// <summary>
        /// Gets the immediate descendant configuration sub-sections.
        /// </summary>
        /// <returns>The configuration sub-sections.</returns>
        IEnumerable<IConfigurationSection> GetChildren();

        /// <summary>
        /// Returns a <see cref="IChangeToken"/> that can be used to observe when this configuration is reloaded.
        /// </summary>
        /// <returns>An <see cref="IChangeToken"/> token if this provider supports change tracking; otherwise, <see langword="null" />.</returns>
        IChangeToken GetReloadToken();
    }
    
    /// <summary>
    /// Represents a section of application configuration values.
    /// </summary>
    public interface IConfigurationSection : IConfiguration
    {
        /// <summary>
        /// Gets the key this section occupies in its parent.
        /// </summary>
        string Key { get; }

        /// <summary>
        /// Gets the full path to this section within the <see cref="IConfiguration"/>.
        /// </summary>
        string Path { get; }

        /// <summary>
        /// Gets or sets the section value.
        /// </summary>
        string? Value { get; set; }
    }
}
```

## **`IConfigurationRoot`（接口）**
- `IConfigurationRoot` 继承自 `IConfiguration`，它代表配置的根节点。它是 `ConfigurationBuilder.Build()` 方法创建的对象，通常是整个配置系统的顶层对象。    
- 它除了支持 `IConfiguration` 的基本操作外，还提供了 `Reload()` 方法，可以在配置文件发生变化时重新加载配置。
```csharp
    /// <summary>
    /// Represents the root of an <see cref="IConfiguration"/> hierarchy.
    /// </summary>
    public interface IConfigurationRoot : IConfiguration
    {
        /// <summary>
        /// Forces the configuration values to be reloaded from the underlying <see cref="IConfigurationProvider"/> providers.
        /// </summary>
        void Reload();

        /// <summary>
        /// Gets the <see cref="IConfigurationProvider"/> providers for this configuration.
        /// </summary>
        IEnumerable<IConfigurationProvider> Providers { get; }
    }
    /// <summary>
    /// Provides configuration key/values for an application.
    /// </summary>
    public interface IConfigurationProvider
    {
        /// <summary>
        /// Tries to get a configuration value for the specified key.
        /// </summary>
        /// <param name="key">The key.</param>
        /// <param name="value">When this method returns, contains the value for the specified key.</param>
        /// <returns><see langword="true" /> if a value for the specified key was found, otherwise <see langword="false" />.</returns>
        bool TryGet(string key, out string? value);

        /// <summary>
        /// Sets a configuration value for the specified key.
        /// </summary>
        /// <param name="key">The key.</param>
        /// <param name="value">The value.</param>
        void Set(string key, string? value);

        /// <summary>
        /// Attempts to get an <see cref="IChangeToken"/> for change tracking.
        /// </summary>
        /// <returns>An <see cref="IChangeToken"/> token if this provider supports change tracking, <see langword="null"/> otherwise.</returns>
        IChangeToken GetReloadToken();

        /// <summary>
        /// Loads configuration values from the source represented by this <see cref="IConfigurationProvider"/>.
        /// </summary>
        void Load();

        /// <summary>
        /// Returns the immediate descendant configuration keys for a given parent path based on the data of this
        /// <see cref="IConfigurationProvider"/> and the set of keys returned by all the preceding
        /// <see cref="IConfigurationProvider"/> providers.
        /// </summary>
        /// <param name="earlierKeys">The child keys returned by the preceding providers for the same parent path.</param>
        /// <param name="parentPath">The parent path.</param>
        /// <returns>The child keys.</returns>
        IEnumerable<string> GetChildKeys(IEnumerable<string> earlierKeys, string? parentPath);
    }
```
## **`ConfigurationBuilder`（类）**
- `ConfigurationBuilder` 它是配置系统的构建器。
-  用于构建一个配置系统，并将不同的配置源（如 JSON 文件、环境变量、命令行参数等）整合成一个统一的 `IConfigurationRoot` 对象。    
- 你可以使用 `AddJsonFile()`、`AddEnvironmentVariables()` 等方法将不同的配置源添加到构建器中，最后通过 `Build()` 方法生成 `IConfigurationRoot`。
```csharp
    /// <summary>
    /// Builds key/value-based configuration settings for use in an application.
    /// </summary>
    public class ConfigurationBuilder : IConfigurationBuilder
    {
        private readonly List<IConfigurationSource> _sources = new();

        /// <summary>
        /// Gets the sources used to obtain configuration values.
        /// </summary>
        public IList<IConfigurationSource> Sources => _sources;

        /// <summary>
        /// Gets a key/value collection that can be used to share data between the <see cref="IConfigurationBuilder"/>
        /// and the registered <see cref="IConfigurationProvider"/> providers.
        /// </summary>
        public IDictionary<string, object> Properties { get; } = new Dictionary<string, object>();

        /// <summary>
        /// Adds a new configuration source.
        /// </summary>
        /// <param name="source">The configuration source to add.</param>
        /// <returns>The same <see cref="IConfigurationBuilder"/>.</returns>
        public IConfigurationBuilder Add(IConfigurationSource source)
        {
            ArgumentNullException.ThrowIfNull(source);

            _sources.Add(source);
            return this;
        }

        /// <summary>
        /// Builds an <see cref="IConfiguration"/> with keys and values from the set of providers registered in
        /// <see cref="Sources"/>.
        /// </summary>
        /// <returns>An <see cref="IConfigurationRoot"/> with keys and values from the registered providers.</returns>
        public IConfigurationRoot Build()
        {
            var providers = new List<IConfigurationProvider>();
            foreach (IConfigurationSource source in _sources)
            {
                IConfigurationProvider provider = source.Build(this);
                providers.Add(provider);
            }
            return new ConfigurationRoot(providers);
        }
    }
    /// <summary>
    /// Represents a source of configuration key/values for an application.
    /// </summary>
    public interface IConfigurationSource
    {
        /// <summary>
        /// Builds the <see cref="IConfigurationProvider"/> for this source.
        /// </summary>
        /// <param name="builder">The <see cref="IConfigurationBuilder"/>.</param>
        /// <returns>An <see cref="IConfigurationProvider"/></returns>
        IConfigurationProvider Build(IConfigurationBuilder builder);
    }
```
## **`ConfigurationProvider`（抽象类）**
`ConfigurationProvider` 是配置提供程序的抽象基类。它负责从某个数据源加载配置项（例如，JSON 文件、环境变量、命令行等）。

 ```csharp
     /// <summary>
    /// Defines the core behavior of configuration providers and provides a base for derived classes.
    /// </summary>
    public abstract class ConfigurationProvider : IConfigurationProvider
    {
        private ConfigurationReloadToken _reloadToken = new ConfigurationReloadToken();

        /// <summary>
        /// Initializes a new <see cref="IConfigurationProvider"/>.
        /// </summary>
        protected ConfigurationProvider()
        {
            Data = new Dictionary<string, string?>(StringComparer.OrdinalIgnoreCase);
        }

        /// <summary>
        /// Gets or sets the configuration key-value pairs for this provider.
        /// </summary>
        protected IDictionary<string, string?> Data { get; set; }
        ...
	}
 ```
**常用子类**：
- `JsonConfigurationProvider`：读取和解析 JSON 文件。    
- `EnvVarConfigurationProvider`：从系统的环境变量中读取配置。

## **`IOptions<T>`（接口）**
`IOptions<T>` 用于访问应用程序配置中的特定部分，并且能够提供配置的即时快照。它常用于 ASP.NET Core 中，帮助在应用程序中管理和注入配置。        
`IOptions<T>` 会将配置绑定到一个类型 `T` 上，这样你就可以通过注入 `IOptions<T>` 获取配置对象。
```csharp
    /// <summary>
    /// Retrieves configured <typeparamref name="TOptions"/> instances.
    /// </summary>
    /// <typeparam name="TOptions">The type of options being requested.</typeparam>
    public interface IOptions<[DynamicallyAccessedMembers(Options.DynamicallyAccessedMembers)] out TOptions>
        where TOptions : class
    {
        /// <summary>
        /// Gets the default configured <typeparamref name="TOptions"/> instance.
        /// </summary>
        TOptions Value { get; }
    }
```
## **`IOptionsMonitor<T>`（接口）**
`IOptionsMonitor<T>`允许在配置更改时接收通知。 提供了对配置项的实时监控。它支持动态更新配置，在配置文件发生变化时能够通知应用程序。
如果你需要在应用程序运行时监控配置的变化并作出响应，`IOptionsMonitor<T>` 是理想的选择。
```csharp
    /// <summary>
    /// Monitors changes on a <typeparamref name="TOptions"/> instance.
    /// </summary>
    /// <typeparam name="TOptions">The options type.</typeparam>
    public interface IOptionsMonitor<[DynamicallyAccessedMembers(Options.DynamicallyAccessedMembers)] out TOptions>
    {
        /// <summary>
        /// Gets the current <typeparamref name="TOptions"/> instance with the <see cref="Options.DefaultName"/>.
        /// </summary>
        TOptions CurrentValue { get; }

        /// <summary>
        /// Returns a configured <typeparamref name="TOptions"/> instance with the given <paramref name="name"/>.
        /// </summary>
        /// <param name="name">The name of the <typeparamref name="TOptions"/> instance. If <see langword="null"/>, <see cref="Options.DefaultName"/>, which is the empty string, is used.</param>
        /// <returns>The <typeparamref name="TOptions"/> instance that matches the given <paramref name="name"/>.</returns>
        TOptions Get(string? name);

        /// <summary>
        /// Registers a listener to be called whenever a named <typeparamref name="TOptions"/> changes.
        /// </summary>
        /// <param name="listener">The action to be invoked when <typeparamref name="TOptions"/> has changed.</param>
        /// <returns>An <see cref="IDisposable"/> that should be disposed to stop listening for changes.</returns>
        IDisposable? OnChange(Action<TOptions, string?> listener);
    }
```  
## **`IOptionsSnapshot<T>`（接口）**    
   `IOptionsSnapshot<T>` 用于按请求获取配置的快照，通常用于需要根据请求动态加载配置的场景。它在每个请求中提供新的配置实例。

## **配置加载**：    
- 在程序启动时，通过 `ConfigurationBuilder()` 来加载多个配置源（例如 JSON 文件、环境变量、命令行参数）。        
- `ConfigurationBuilder` 会调用不同的配置提供程序来加载数据，并将其合并为一个统一的 `IConfigurationRoot` 对象。    
- 
在 ASP.NET Core 中加载配置
```csharp
public class Program
{
    public static void Main(string[] args)
    {
        // Create a host builder with default configuration settings
        CreateHostBuilder(args).Build().Run();
    }

    public static IHostBuilder CreateHostBuilder(string[] args) =>
        Host.CreateDefaultBuilder(args)
            .ConfigureAppConfiguration((context, config) =>
            {
                // You can add custom configuration files if necessary
                config.AddJsonFile("appsettings.json", optional: false, reloadOnChange: true)
                      .AddJsonFile($"appsettings.{context.HostingEnvironment.EnvironmentName}.json", optional: true)
                      .AddEnvironmentVariables(); // Support environment variables
            })
            .ConfigureWebHostDefaults(webBuilder =>
            {
                webBuilder.UseStartup<Startup>();
            });
}
```
**`CreateDefaultBuilder()` 方法** 会自动加载如下配置：
- `appsettings.json`    
- `appsettings.{Environment}.json`（例如，`appsettings.Development.json` 或 `appsettings.Production.json`）    
- 环境变量    
- 命令行参数

在非 ASP.NET Core 项目中加载配置。对于非 Web 项目（例如控制台应用程序），你可以在 Main 方法中手动加载 JSON 配置文件。
```csharp
using Microsoft.Extensions.Configuration;

public class Program
{
    public static void Main(string[] args)
    {
        // 手动加载 appsettings.json
        var configuration = new ConfigurationBuilder()
            .SetBasePath(Directory.GetCurrentDirectory()) // 配置文件路径
            .AddJsonFile("appsettings.json", optional: false, reloadOnChange: true)
            .Build();

        // 获取配置数据
        var mySetting = configuration["MySetting"];
        Console.WriteLine($"MySetting: {mySetting}");
    }
}
```
- **`ConfigurationBuilder`**：用于构建配置源。    
- **`AddJsonFile`**：将 `appsettings.json` 文件作为配置源添加。    
- **`Build`**：构建最终的配置对象。    
- **`configuration["MySetting"]`**：读取配置。

如果你有一个配置类，可以将配置文件的内容直接绑定到该类：
```csharp
public class MySettings
{
    public string MySetting { get; set; }
}

public class Program
{
    public static void Main(string[] args)
    {
        var configuration = new ConfigurationBuilder()
            .SetBasePath(Directory.GetCurrentDirectory())
            .AddJsonFile("appsettings.json", optional: false, reloadOnChange: true)
            .Build();

        // 绑定配置到对象
        var mySettings = configuration.GetSection("MySettings").Get<MySettings>();

        Console.WriteLine($"MySetting: {mySettings.MySetting}");
    }
}
```
**`GetSection("MySettings").Get<MySettings>()`**：将 `appsettings.json` 文件中的 `MySettings` 配置部分绑定到 `MySettings` 类。
## **配置访问**：    
- 应用可以通过 `IConfiguration` 接口来访问配置中的值。        
- 可以通过 `GetSection` 获取特定部分的配置，或者直接通过索引器获取某个键的值。        
## **配置绑定**：    
- 使用 `IOptions<T>` 可以将配置绑定到一个 C# 类中，以便更方便地使用和维护。        
## 动态配置更新**：    
- 使用 `IOptionsMonitor<T>` 或 `IOptionsSnapshot<T>` 可以动态获取和监控配置的变化，适用于需要动态更新配置的场景。

# FAQ
## 下面2种有什么区别？
```csharp
var appSettings = configuration.GetSection("AppSettings").Get<AppSettings>();
```
- **功能**：从 `IConfiguration` 中读取 `"AppSettings"` 部分的配置，并直接绑定到一个新的 `AppSettings` 实例。    
- **使用场景**：这种方式通常用于**一次性读取配置**，例如在应用程序中直接读取配置数据并保存到本地变量中，然后使用。    
- **生命周期**：读取后，配置会立即被绑定到 `AppSettings` 类，并返回该实例。绑定的数据不会随配置文件的变化而更新（即没有动态监控）。
```csharp
services.Configure<AppSettings>(configuration.GetSection("AppSettings"));
```
- **功能**：通过 `IServiceCollection` 向依赖注入容器注册一个配置绑定。这个方法将 `IConfiguration` 中的 `"AppSettings"` 部分绑定到 `AppSettings` 类型，并让 DI 容器负责管理该对象的生命周期。    
- **使用场景**：这种方式通常用于**依赖注入**和**动态配置管理**，使得配置可以在应用程序中注入到服务类中，并且在应用运行时能够根据需要提供配置数据。    
- **生命周期**：这个配置对象是由 **依赖注入容器**管理的，通常绑定到 **Singleton** 或 **Scoped** 生命周期。
- 这里 `AppSettings` 类通过 `IOptions<AppSettings>` 的方式进行依赖注入。配置可以在应用程序的任何地方通过 DI 获取，并且支持在运行时根据需要更新配置（例如通过使用 `IOptionsMonitor<AppSettings>`）。
## .NET中什么是host？什么是builder？之间的关系是什么？
**Host** 是 .NET 应用程序的核心，它负责管理应用的生命周期，包括服务容器（DI）、日志、配置等的初始化和启动。在 .NET 中，主要有两种核心的 Host 类型：

|**特性**|**通用 Host (IHost)**|**Web Host (IWebHost / WebApplication)**|
|---|---|---|
|**基础**|核心 Host，独立于 Web|核心 Host + Web 功能|
|**主要功能**|DI, Logging, Config, Hosted Services|**+ HTTP Server (Kestrel)**, Middleware, Routing|
|**应用场景**|后台服务、控制台应用、Worker Service|Web API, MVC, Blazor 应用|
|**依赖**|`Microsoft.Extensions.Hosting`|`Microsoft.AspNetCore.App`|
### 通用 Host (Generic Host) - `IHost`
通用 Host 是最基础、最灵活的 Host。它用于运行**任何类型的 .NET 应用**，尤其是那些不需要 Web 功能（如 HTTP 服务器）的应用。
- **核心接口:** `Microsoft.Extensions.Hosting.IHost`    
- **用途:**    
    - **控制台应用 (Console Apps):** 运行命令行工具或后台处理器。        
    - **后台服务 (Background Services):** 运行不需要用户界面的长期任务，例如 Windows Service 或 Linux Daemon。        
    - **定时任务 (Scheduled Jobs):** 管理定期执行的清理或数据处理任务。        
- **创建方式:** 使用 `Host.CreateDefaultBuilder()` 方法创建。
### Web Host (Web Host) - `IWebHost` / WebApplication
Web Host 是在通用 Host 基础上构建的，专门用于运行 **Web 应用程序**（如 ASP.NET Core）。它在通用 Host 的功能之外，额外集成了处理 HTTP 请求的能力。
- **核心接口:** `Microsoft.AspNetCore.Hosting.IWebHost` (传统) 和 `WebApplication` (现代 Minimal APIs)    
- **用途:**    
    - **Web API:** 托管 RESTful 服务。        
    - **MVC 应用:** 托管传统的 Web 页面应用。        
    - **Blazor Server 应用:** 托管实时 Web 应用。        
- **创建方式:**    
    - **传统:** 使用 `WebHost.CreateDefaultBuilder()`。        
    - **现代 (推荐):** 使用 `WebApplication.CreateBuilder(args)`，这种方式集成了通用 Host 的所有功能，并且是 ASP.NET Core 6+ 的默认方式。
### Builder（构建器）是一种设计模式，它是创建和配置 Host 对象的核心机制。
简单来说，您不能直接创建一个配置完善的 Host 对象。您必须先通过一个 Builder，分步配置各种组件，最后再调用 Builder 上的方法来“构建”出最终的 Host 实例。
在 .NET 中，最常见的 **Builder** 主要有以下几种：
```
                            +---------------------------+
                            |    Application Host       |
                            +---------------------------+
                                       |
                        +-----------------------------------------+
                        |                                         |
              +------------------+                        +------------------+
              |    HostBuilder    |                        |  WebHostBuilder   |
              +------------------+                        +------------------+
                        |                                         |
                +------------------+                        +------------------+
                |       IHost      |                        |     IWebHost      |
                |   (Generic Host)  |                        |    (Web Host)     |
                +------------------+                        +------------------+
                        |                                         |
                +----------------------------+             +-------------------+
                |   ServiceCollection         |             |   Http Server     |
                |   (Dependency Injection)    |             |   (Kestrel)       |
                +----------------------------+             +-------------------+
                        |                                         |
                +----------------------------+            +-------------------+
                |   Configuration             |            |   Middleware      |
                |   (IConfiguration)          |            |   (Request Pipeline)|
                +----------------------------+            +-------------------+
                        |
              +------------------------------+
              |  ConfigurationBuilder        |
              |   (Build Configuration)      |
              +------------------------------+
                        |
              +------------------------------+
              |   IConfigurationRoot         |
              |  (Unified Configuration)     |
              +------------------------------+
                        |
              +------------------------------+
              |       IOptions<T>            |
              |   (Bind to POCO Classes)     |
              +------------------------------+
                        |
              +------------------------------+
              |  AppSettings / Custom Config |
              +------------------------------+
```
**`ConfigurationBuilder`**：
- 用于构建和加载应用程序的配置（例如 JSON 文件、环境变量、命令行参数等）。它通过多个配置源将配置数据汇聚成一个统一的 `IConfiguration` 对象。    
- **用途**：在应用程序启动时，通常用于从多个来源加载配置并构建出一个配置对象。
```csharp
// 手动创建configuration builder
var configuration = new ConfigurationBuilder()
    .SetBasePath(Directory.GetCurrentDirectory())
    .AddJsonFile("appsettings.json", optional: false, reloadOnChange: true)
    .Build();
```
**`HostBuilder`**（或者 `IHostBuilder`）：
- 用于构建和启动应用程序的主机。它负责初始化和管理应用的生命周期，包括服务的配置、依赖注入、日志和其他相关服务。    
- **用途**：在 ASP.NET Core 或控制台应用程序中，`HostBuilder` 通常用于设置应用程序的生命周期，配置 DI 容器、日志、配置等，并启动应用。
```csharp
var host = Host.CreateDefaultBuilder(args)
    .ConfigureServices((context, services) =>
    {
        // 注册服务
    })
    .Build();
host.Run();
```
**`WebHostBuilder`**（ASP.NET Core 特有）：
- 在 ASP.NET Core 项目中，`WebHostBuilder` 用于构建 Web 主机，它是 `IHostBuilder` 的一种特殊化，用于 Web 应用程序的配置和启动。    
- **用途**：用于构建和启动 ASP.NET Core Web 应用，配置 HTTP 请求管道、控制器等 Web 相关的服务。
```csharp
var webHost = WebHost.CreateDefaultBuilder(args)
    .Configure(app =>
    {
        // 配置中间件
    })
    .Build();
webHost.Run();
```
**`ServiceCollection`**：
- 用于构建和配置 DI 容器。通过 `IServiceCollection`，你可以注册应用程序中所需的所有服务、配置等。
```csharp
var services = new ServiceCollection();
services.AddTransient<MyService>();
var serviceProvider = services.BuildServiceProvider();
```
## `builder` 能配置多少种 service？
通过 `HostBuilder`，你可以配置很多不同类型的服务，主要通过以下几种方式：
1. **配置文件和其他配置源（Configuration）**：    
    - 配置应用程序的配置源，加载 JSON 文件、环境变量、命令行参数等。        
    - 在 `ConfigureAppConfiguration`() 中做很多定制，添加不同的配置源、设置默认配置等。
2. **依赖注入（Dependency Injection, DI）**：    
    - 注册应用程序中需要的各种服务（如：数据库连接、第三方 API 客户端等）。        
    - 在 `ConfigureServices`() 中，可以使用多种服务生命周期：`Singleton`、`Scoped`、`Transient`。        
    - 支持后台任务、消息队列处理等服务的注册。        
3. **日志记录（Logging）**：    
    - 配置日志输出，设置日志级别、添加日志提供程序等。        
    - 在 `ConfigureLogging` 中可以设置不同的日志输出目标（如：控制台、文件、第三方日志服务等）。        
4. **主机特性/托管的后台服务（Host Features）**：    
    - 启动和配置一个应用程序的生命周期、健康检查、托管后台服务等。        
5. **Web 主机特性/健康检查、生命周期管理（WebHost）**：    
    - 如果是 Web 应用，可以使用 `WebHostBuilder` 设置 Kestrel 服务器、MVC、Razor 页面等 Web 相关的服务和中间件。
```csharp
var builder = Host.CreateDefaultBuilder(args)
    .ConfigureAppConfiguration((hostContext, config) =>
    {
        // 1. 配置：从 appsettings.json, 环境变量等加载设置
        config.AddJsonFile("appsettings.Custom.json", optional: true);
    })
    .ConfigureServices((hostContext, services) =>
    {
        // 2. 依赖注入（DI）：注册服务
        services.AddSingleton<IDataService, SqlDataService>();
        services.AddHostedService<WorkerService>(); // 注册后台任务
    })
    .ConfigureLogging(logging => 
    {
        // 3. 日志：配置日志级别和输出目标
        logging.AddConsole();
        logging.SetMinimumLevel(LogLevel.Warning);
    });
```
