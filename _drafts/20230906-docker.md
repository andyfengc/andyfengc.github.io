# Introduction
Docker is a container management service. The whole idea of docker is for developers to easily develop applications, ship them into containers and deploy anywhere.
> docker was released in March 2013.

**Docker** 是一个开源的平台软件，用于**容器化**应用程序。它允许开发者将应用程序及其所有依赖项（包括库、系统工具、代码和运行时环境）打包到一个标准化、可移植的单元中，这个单元就是**容器 (Container)**。
> 虚拟机：虚拟出一个完整操作系统 
> Docker：共享宿主机系统，只隔离应用环境.Docker 容器启动更快、占用更小、迁移更方便。
## Docker vs 虚拟机

|项目|Docker 容器|虚拟机|
|---|---|---|
|启动速度|秒级|分钟级|
|性能|接近原生|较低|
|体积|MB 级|GB 级|
|隔离性|进程级隔离|系统级隔离|
|使用场景|微服务、测试、部署|独立系统、完整环境|
# Docker 的核心组件
## 镜像 (Image)
- **定义：** 镜像是类似操作系统的“快照模板”，包含应用代码和依赖。一个**只读**的模板，包含了应用程序运行所需的一切：代码、运行时、系统库、环境变量和配置文件。    
- Image是只读的
- **作用：** 它是创建容器的**蓝图**。就像面向对象编程中的“类”，镜像本身是静态的。    
- **特性：** 镜像采用**分层存储**（Union File System），每层都是一个指令的产物，这种结构使其体积小、传输快。
## 容器 (Container)
- **定义：** 容器是从镜像启动的运行实例。它是 Docker 应用程序的实际运行实体。    
- Container = Image + Container Layer（可写层, 容器内发生的所有文件修改、创建、删除都写入这一层）。
- **作用：** 容器是**隔离**的沙盒环境。每个容器彼此独立，与宿主机隔离，确保了安全和互不干扰。   
- **特性：** 容器在启动时会在只读的镜像层之上添加一个**可读写层**（Writeable Layer），所有运行时的数据和修改都保存在这一层。容器停止或删除后，可读写层通常会被清除（除非使用卷 Volume），但底层的镜像保持不变。
## 数据持久化
Docker 提供了几种数据持久化方式，其中最主流的是 Volume 和 Bind Mount。
### Volume（数据卷）
Docker 自己管理的存储，容器删除不丢失。数据卷用于在宿主机与容器之间共享或持久化数据。
e.g. 
```yaml
volumes:
  n8n_data:

services:
  n8n:
    image: n8nio/n8n:latest
    container_name: n8n
    volumes:
      - n8n_data:/home/node/.n8n
```
- `n8n_data` → Docker 管理的卷    
- `/home/node/.n8n` → 容器内部路径    
- n8n 的工作流、凭证、配置会存到这个卷里    
- **好处**：删除容器数据还在，跨容器也可用    
- **缺点**：宿主机上不直接看到文件
#### 管理 Volume（创建、查看、删除）
Volume 是独立于容器存在的 Docker 对象。 Docker 推荐用于生产环境的首选数据持久化方式。
路径:

| **操作系统**    | **Volume 默认存储路径**                         |
| ----------- | ----------------------------------------- |
| **Linux**   | `/var/lib/docker/volumes/` 下的各个子目录        |
| **Windows** | 如果使用 WSL 2 后端，Volume 存储在 WSL 2 虚拟机的文件系统内。 |
| **macOS**   | Volume 存储在运行 Docker Desktop 的虚拟机的文件系统内。   |
创建数据卷
```bash
docker volume create mydata
```
查看 Volume
```bash
docker volume ls
```
查看某个 Volume 的详细信息（包括它在宿主机上的实际路径）：
```bash
docker volume inspect my_data_volume
```
删除 Volume. **注意：** 必须先停止并删除使用该 Volume 的容器才能删除 Volume 本身。
```bash
docker volume rm my_data_volume
```
#### 挂载 Volume 到容器
在运行容器时，使用 -v 或 --mount 标志来挂载 Volume。
```
# 挂载目录
docker run -v /home/user/data:/data ubuntu
```
命名 Volume (Named Volume) 。格式为：[Volume 名称]:[容器内路径]。
示例： 运行一个 Nginx 容器，并将 my_data_volume 挂载到容器内的 /usr/share/nginx/html 路径。
```
docker run -d \
  --name web_server \
  -v my_data_volume:/usr/share/nginx/html \
  nginx:latest
```
效果： 容器对 /usr/share/nginx/html 目录的所有读写操作，都会被持久化到宿主机上由 Docker 管理的 my_data_volume 中。即使容器被删除，数据依然安全。

匿名 Volume (Anonymous Volume) 只指定容器内的路径，不指定 Volume 名称。Docker 会自动创建一个随机命名的 Volume。
```
docker run -d \
  -v /app/data \
  my_app_image
```
**注意：** 这种 Volume 较难管理和引用。
### Bind Mount (绑定挂载) 的使用
将宿主机的文件夹映射到容器中，容器可直接访问电脑文件
e.g. 
```yaml
volumes:
  - "C:/Users/Owner/n8n-files:/data"
```
- 左边 `C:/Users/Owner/n8n-files` → 你 Windows 上的目录    
- 右边 `/data` → 容器内部路径    
- 容器里的程序访问 `/data` 就相当于在操作你电脑的 `C:\Users\Owner\n8n-files`    
- **好处**：    
    - 容器直接操作本地文件        
    - 文件可在 Windows 上编辑或新增        
- **注意**：    
    - Windows 需要在 Docker Desktop → Settings → Resources → File Sharing 授权访问(optional)        
    - 权限不足或路径写错，容器会找不到文件

Bind Mount 是 Docker 推荐用于本地开发、测试环境的方式。直连本地硬盘的一个特定文件夹 💻
挂载 Bind Mount 到容器，格式为：[宿主机绝对路径]:[容器内路径]。
示例： 将您本地的 /home/user/my-code 目录直接挂载到容器内的 /app 目录。
```
# 假设您在 Windows 使用 PowerShell/CMD，路径可能需要引号
docker run -d \
  --name dev_app \
  -v "C:\Users\YourName\my-code:/app" \
  my_development_image
```
**效果：** 您在宿主机上修改 `/home/user/my-code` 目录下的代码文件时，容器内的 `/app` 目录会**实时同步更新**。这极大地加快了本地开发和测试的速度。
### volume vs bind mount
- 对于 **Volume**，Docker 会将镜像中的数据**复制**到新建的 Volume 中。    
- 对于 **Bind Mount**，Docker 会直接使用宿主机上的数据，**覆盖**容器镜像中的原有数据。

| **挂载方式**       | **宿主机路径**                                         | **命令格式**                                       | **核心区别**                |
| -------------- | ------------------------------------------------- | ---------------------------------------------- | ----------------------- |
| **Volume**     | **Docker 自动管理**（通常在 `/var/lib/docker/volumes/` 下） | `-v my_volume_name:/path/in/container`         | 数据独立于宿主机结构，**最安全、最推荐**。 |
| **Bind Mount** | **用户指定**的宿主机上的任意绝对路径                              | `-v /absolute/path/on/host:/path/in/container` | 路径明确，**方便本地开发调试**。      |
在 docker run 命令中，都可以使用 -v 或 --mount 参数来实现数据挂载，效果一样。
-v的格式通常为：<源>:<目标>[:权限]

|**字段**|**含义**|**Bind Mount 示例**|**Volume 示例**|
|---|---|---|---|
|**`<源>`**|**宿主机上的数据源。**|**`/host/absolute/path`** (宿主机绝对路径)|**`my_volume_name`** (已命名的 Volume 名称)|
|**`<目标>`**|**容器内希望挂载到的路径。**|**`/app/data`**|**`/var/www/html`**|
|**`[:权限]`**|可选。指定容器对数据的权限。|**`:ro`** (Read Only，只读)|**`:ro`** (Read Only，只读)|
e.g. 
Bind Mount： 将本地的 /home/user/app 挂载到容器的 /app 目录，并设置为只读。
```
docker run -v /home/user/app:/app:ro my_image
```
**Volume：** 将名为 `db_data` 的 Volume 挂载到容器的 `/var/lib/mysql` 目录。
```
docker run -v db_data:/var/lib/mysql mysql:latest
```
n8n 使用 Volume 和 Bind Mount 的组合
```yaml
volumes:
  n8n_data:

services:
  n8n:
    image: n8nio/n8n:latest
    container_name: n8n
    ports:
      - "5678:5678"
    environment:
      - GENERIC_TIMEZONE=Canada/Eastern
    volumes:
      # 1️⃣ 持久化工作流和凭证
      - n8n_data:/home/node/.n8n
      # 2️⃣ 读取本地文件
      - "C:/Users/Owner/n8n-files:/data"
```
- `/home/node/.n8n` → 容器存储 n8n 自己数据    
- `/data` → 容器可以访问 Windows 文件 `C:\Users\Owner\n8n-files`
在 n8n 节点里：
`读取文件路径：/data/test.txt`

就对应 Windows 上：
`C:\Users\Owner\n8n-files\test.txt`
### 备份volume数据
备份
```powershell
docker run --rm -v n8n-workflow_n8n_data:/data -v C:/delete/backup:/backup n8nio/n8n tar cvf /backup/db_data_(Get-Date -Format 'yyyy-MM-dd').tar /data
```
> 原理：创建一个临时的容器，把指定volume挂载到容器内的 /data 目录，把备份文件夹挂载到容器内的 /backup 目录，，然后使用 tar 命令备份，最后 --rm删除临时容器
> 待备份的volume名称 n8n-workflow_n8n_data
> 备份container名称 n8nio/n8n
> 备份到文件夹 C:/delete/backup
> 备份文件名 n8n_backup_yyyy-MM-dd.tar
> alpine 是一个包含 `tar` 的轻量级镜像来执行压缩备份

恢复
首先确认目标volume已经存在。
如果n8n应用已经运行，那么volume就应该存在。
如果是全新的环境，那么就先创建volume
```
docker volume create n8n-workflow_n8n_data
```
执行恢复命令
```powershell
$BackupFile = "[备份文件名]"
docker run --rm -v n8n-workflow_n8n_data:/data -v C:/delete/backup:/backup alpine tar -xvf "/backup/$BackupFile" -C /data --strip-components 1
```
> 原理：创建一个临时的容器，将备份文件所在的目录和目标 Volume 同时挂载进去，然后使用 tar 命令将备份文件解压到目标 Volume 中。
> 将备份文件所在的目录 (`C:/delete/backup`)挂载到临时容器
> 将目标 Volume (`n8n-workflow_n8n_data`) 挂载到临时容器
> 执行解压命令 **`tar -xvf ...。x (Extract): 解压文件；v (Verbose): 显示详细过程；f (File): 指定输入文件。

## Dockerfile
描述如何构建镜像的脚本文件。
用于定义如何构建您自己的镜像

Node.js 应用镜像构建示例：
```dockerfile
# 基础镜像
FROM node:18

# 设置工作目录
WORKDIR /app

# 拷贝项目文件
COPY package*.json ./

# 安装依赖
RUN npm install

# 拷贝所有文件
COPY . .

# 暴露端口
EXPOSE 3000

# 启动命令
CMD ["npm", "start"]
```
构建命令：
```
docker build -t mynodeapp .
docker run -p 3000:3000 mynodeapp
```
## **`Compose`**
用于简化多容器应用的定义和管理
让多个容器之间通信。
`docker-compose.yml` 用于描述多个容器如何协作。
例子（Node.js + MongoDB）：
```yaml
version: '3'
services:
  web:
    build: .
    ports:
      - "3000:3000"
    depends_on:
      - db
  db:
    image: mongo
    volumes:
      - data:/data/db
volumes:
  data:
```
运行：
```
docker-compose up -d
```
## Network（网络）
Docker 默认创建三种网络：

|类型|说明|
|---|---|
|**bridge**|默认网络，容器间通过虚拟网桥通信|
|**host**|直接使用宿主机网络|
|**none**|无网络|
创建自定义网络：
```
docker network create mynet
docker run -d --name db --network mynet mysql
docker run -d --name app --network mynet myapp
```

# Commands
## Image镜像操作
```bash
docker pull <image_name>     # 从仓库拉取(下载)镜像, e.g. ubuntu, n8nio/n8n:latest
docker images                # 列出本地所有镜像
docker rmi <image_id>        # 删除一个本地指定的镜像
```
## 容器命令
```bash
docker run [OPTIONS] <image_name> # 创建并启动一个新的容器
docker run -it ubuntu bash      # 启动交互式容器
docker ps                       # 查看运行中的容器
docker ps -a                    # 列出所有容器（包括已停止的）
docker stop <container_id>      # 停止一个正在运行的容器
docker rm <container_id>        # 删除一个已停止的容器
```
## 构建与日志
```bash
docker build -t <container_id> .         # 使用当前目录Dockerfile构建镜像
docker logs <container_id>               # 查看容器日志
docker exec -it <container_id> bash      # 在运行的容器内执行命令（例如进入容器内部）。
```

# Kubernetes
Kubernetes (K8s) 和 Docker 是云原生领域最重要的两大技术，它们的关系是相辅相成、分工协作的。
> Docker 负责将应用程序“打包”成容器，而 Kubernetes 负责“管理”这些容器的大规模运行。
> Docker 是 K8s 的基础, Docker Engine 最初是 Kubernetes 最流行、最常用的容器运行时。
> 但从 Kubernetes 的 1.20 版本开始，Kubernetes 正在逐步移除对 Docker Engine 的直接支持，转而依赖更底层的、遵守 OCI (开放容器标准) 的容器运行时，例如 Containerd 和 CRI-O。

|**角色/技术**|**Docker**|**Kubernetes (K8s)**|
|---|---|---|
|**主要功能**|**容器运行时/打包工具**|**容器编排/集群管理**|
|**解决了什么问题**|“在我的机器上能跑”的问题（环境一致性）|“如何大规模、可靠地运行上百个容器”的问题|
|**抽象级别**|**单个应用容器**|**整个应用集群和基础设施**|
|**核心组件**|Docker 镜像 (Image)、Docker 容器 (Container)|Pod、Service、Deployment、Node|
|**适用场景**|**开发、构建、单机测试**|**生产环境、高可用、大规模部署**|
**Kubernetes (通常简称为 K8s)** 是一个**开源的容器编排 (Container Orchestration) 平台**。
- **目标：** 自动化部署、扩展和管理容器化应用。    
- **用途：** 当您的应用容器数量达到几十、几百甚至几千个时，手动管理它们（如故障重启、负载均衡、自动扩缩容等）几乎是不可能的。Kubernetes 就是为了解决这种**大规模集群管理**问题而生的“容器操作系统”。

Kubernetes 提供了一套强大的功能来确保您的容器化应用稳定运行：
- 自动部署与回滚： 声明式地描述应用状态，K8s 会自动完成部署，并能轻松回滚到旧版本。
- 服务发现与负载均衡： K8s 为容器提供 DNS 名称，并能在多个容器实例之间分发网络流量。
- 存储编排： 自动挂载存储系统（如云存储、本地存储）。
- 自我修复： 如果容器或节点宕机，K8s 会自动重启失败的容器、替换故障的节点，并重新调度它们。
- 秘密 (Secrets) 与配置管理： 安全地存储和管理敏感信息（如密码、OAuth 令牌）和应用配置。
- 水平扩缩容： 可以根据 CPU 利用率或自定义指标，自动增加或减少运行中的容器数量。

## 重建容器container
**停止并移除容器 (不影响数据卷)。**
使用 `docker compose down` 命令是处理 Docker Compose 部署的最佳方式。它会停止并移除由该配置文件创建的**容器和网络**，但会**保留数据卷**。

在包含您的 `docker-compose.yml` 文件的目录下运行：
```
docker compose down
```

**验证数据卷是否仍然存在 (确保数据安全)。**
```
docker volume ls | findstr n8n-workflow_n8n_data
```

改好yml配置文件，使用新配置重新启动容器。
```
docker compose up -d
```
## 怎么配置国内的镜像加速器
由于 Docker 官方镜像仓库 (Docker Hub) 在国内访问速度可能较慢，建议配置**镜像加速器**：
1. 打开 **Docker Desktop UI**（任务栏上的鲸鱼图标）。    
2. 点击 **Settings (设置) 齿轮图标**。    
3. 进入 **Docker Engine (Docker 引擎)** 选项卡。    
4. 在 JSON 配置中，添加或修改 `registry-mirrors` 字段，例如使用阿里云、华为云或腾讯云提供的加速地址：
```json
{
  "registry-mirrors": [
    "https://<您的加速器地址>.mirror.aliyuncs.com"
  ]
}
```
点击 **Apply & Restart (应用并重启)**。
