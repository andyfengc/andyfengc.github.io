# Introduction
| 方案                            | 类型        | 核心机制                                        | 典型用法                                 |
| ----------------------------- | --------- | ------------------------------------------- | ------------------------------------ |
| **IDataErrorInfo**            | UI绑定接口    | 属性级错误，通过索引器或 `Error` 暴露                     | WPF/WinForms 数据绑定                    |
| **INotifyDataErrorInfo**      | UI绑定接口    | 支持多错误，异步通知，通过事件暴露                           | WPF/MAUI MVVM 绑定                     |
| **ValidationRule**            | XAML 内置规则 | 在 Binding 中定义校验逻辑                           | WPF XAML `<Binding.ValidationRules>` |
| **DataAnnotations**           | 属性/模型特性   | `[Required]`, `[Range]`, `[StringLength]` 等 | MVC/WebAPI/Blazor/WPF                |
| **FluentValidation**          | 验证框架      | C# 配置规则，支持复杂、跨字段、异步                         | MVC/WebAPI/Blazor/WPF/MAUI/Console   |
| **Code-behind 手动校验**          | 手动        | UI事件中直接判断                                   | WPF/WinForms/任何 .NET                 |
| **MVC Filters / API Filters** | 框架拦截      | Controller 层拦截参数校验                          | ASP.NET Core MVC / WebAPI            |
| **自定义校验服务 / Domain 服务**       | 业务层       | 纯 C# 方法                                     | 所有 .NET 平台                           |

|方案|跨平台（UI无关）|支持 UI 绑定|支持异步|支持复杂规则|可复用到 Web/API|备注|
|---|---|---|---|---|---|---|
|IDataErrorInfo|❌|✅|❌|❌|❌|只能桌面 UI，用于 WPF/WinForms|
|INotifyDataErrorInfo|⚠|✅|✅|✅|❌|WPF/MAUI 可用，Web/API 无用|
|ValidationRule|❌|✅|❌|⚠|❌|仅 WPF/XAML Binding|
|DataAnnotations|✅|✅|❌|⚠|✅|简单规则好用，跨平台支持有限制复杂逻辑|
|FluentValidation|✅|✅|✅|✅|✅|企业级首选，真正跨平台，可复用|
|Code-behind 手动|❌|✅|✅|✅|❌|不推荐，破坏 MVVM/可复用性|
|MVC Filters / API Filters|❌|❌|✅|⚠|✅|Web 专用，不可复用到桌面 UI|
|自定义 Domain 校验服务|✅|❌|✅|✅|✅|真正业务层校验，UI 框架无关，可和 FluentValidation 结合|
按通用性分级

| 等级    | 方案                                         | 说明                                      |
| ----- | ------------------------------------------ | --------------------------------------- |
| ⭐⭐⭐⭐⭐ | FluentValidation                           | **全平台通用、企业级、复杂规则可支持异步**<br>适合复杂规则，企业级项目 |
| ⭐⭐⭐⭐  | DataAnnotations                            | 官方支持，简单规则跨平台可用，跨字段/异步能力弱<br>适合简单项目      |
| ⭐⭐    | Domain/Service 层纯 C# 校验                    | UI 框架无关，可复用，但需自己写规则                     |
| ⭐⭐    | INotifyDataErrorInfo                       | 仅 UI 桌面可用，不能 Web/API 共用                 |
| ⭐     | IDataErrorInfo                             | 老技术，仅限UI桌面端，不能 Web/API 共用               |
| ⚠     | ValidationRule / Code-behind / MVC Filters | 平台绑定或非通用，适合小项目/临时处理                     |
## 架构建议
1. 业务规则在 Domain/Application 层   
    - 使用 FluentValidation 或**自定义业务方法** 来做核心业务校验

2. **UI 只负责显示错误**    
    - WPF → 可用 INotifyDataErrorInfo 显示        
    - Blazor → 显示 ValidationMessage        
    - Web → 自动绑定 ModelState

3. **轻量项目**    
    - 仅 DataAnnotations + XAML/Blazor 校验即可
        
4. **桌面 UI 临时方案**    
    - IDataErrorInfo / ValidationRule 可用，但不推荐在大型项目

- **如果你在做 Web API**：直接用 **FluentValidation**。它在 Web 端的集成体验极佳。    
- **如果你在做简单的 WPF/Blazor 表单**：直接用 **DataAnnotations**。    
- **如果你在做复杂的 WPF 客户端**：使用 **INotifyDataErrorInfo** 作为底层，但在内部调用 **FluentValidation** 的逻辑。这样既能享受 WPF 的异步红框提示，又能保持校验代码的优雅。

最佳实践：
- 领域层用 **FluentValidation 或自定义业务方法** 来做核心业务校验    
- DTO / ViewModel 用 **DataAnnotations** 做 UI / 数据输入级别的同步校验    
- UI 层和 API 层直接利用 DataAnnotations 自动显示或返回错误
# DataAnnotations (特性标注)
通过在属性上打“标签”（Attribute）来描述校验规则。它是 .NET 官方的基础方案。
**用在哪些场合：**
- **全平台通用**：Web API、WPF、Blazor、Entity Framework (数据库生成)。    
- 用 **特性（Attribute）** 标记属性规则，例如必填、长度、范围。    
- 适合简单的**格式校验**（长度、非空、正则）。
- 优势：**跨 UI、跨平台，可用于 WPF、Blazor、MVC、WebAPI 等**。
e.g.
```csharp
public class User
{
    [Required(ErrorMessage = "名称必填")]
    [StringLength(50, MinimumLength = 3, ErrorMessage = "名称长度 3-50")]
    public string Name { get; set; }

    [Range(1, 120, ErrorMessage = "年龄必须在 1-120")]
    public int Age { get; set; }

    [EmailAddress(ErrorMessage = "邮箱格式不正确")]
    public string Email { get; set; }
}
```
**优缺点：**
- **优点**：上手最快，代码量极少。所有 .NET 框架都天然支持。    
- DTO / ViewModel / Model 属性校验    
- 桌面 UI（WPF/MAUI）    
- Web / Blazor / MVC / WebAPI    
- 简单、同步校验为主
- **缺点**：逻辑硬编码在 Model 中；无法处理复杂逻辑（如：如果 A 为 true，则 B 必填）。
- 不支持跨字段逻辑复杂校验    
- 不支持异步

```csharp

var user = new UserModel { Name = "", Age = 130, Email = "abc" };

var results = new List<ValidationResult>();

{
    foreach (var error in results)
```

#### 写一个通用 DTO 验证 API（所有框架都通用）
```csharp
using System.ComponentModel.DataAnnotations;

public static class DtoValidator
{
    public static IReadOnlyList<ValidationResult> Validate(object dto)
    {
        var results = new List<ValidationResult>();
        var context = new ValidationContext(dto);

        Validator.TryValidateObject(
            dto,
            context,
            results,
            validateAllProperties: true
        );

        return results;
    }

    public static bool IsValid(object dto, out IReadOnlyList<ValidationResult> errors)
    {
        errors = Validate(dto);
        return errors.Count == 0;
    }
}
```

```csharp
public class ChannelAddViewModel : IDataErrorInfo
```

跨字段校验怎么办？DTO 里用 IValidatableObject
```csharp
public sealed class UserEditDto : IValidatableObject
{
    public string Password { get; set; } = string.Empty;
    public string ConfirmPassword { get; set; } = string.Empty;

    public IEnumerable<ValidationResult> Validate(ValidationContext context)
    {
        if (Password != ConfirmPassword)
        {
            yield return new ValidationResult(
                "Passwords do not match",
                new[] { nameof(ConfirmPassword) });
        }
    }
}
```

# FluentValidation— 社区事实标准
FluentValidation是第三方开源验证框架，使用“链式调用”（Fluent Interface）将校验逻辑与模型类完全分离。纯 C# 写规则，强类型，支持复杂规则、跨字段、异步
**用在哪些场合：
- 可用于 **WPF / MAUI / Blazor / Web API / MVC / Console / Worker 等全平台**
- **中大型项目**：逻辑复杂、需要高度可测试性的项目。    
- 适合**业务逻辑校验**（如：去数据库查重、根据不同条件切换规则）。
你需要定义一个独立的验证器类：
```csharp
using FluentValidation;

public class UserValidator : AbstractValidator<User>
{
    public UserValidator()
    {
        RuleFor(x => x.Name)
            .NotEmpty().WithMessage("不能为空")
            .Length(2, 10).When(x => x.IsActive); // 支持条件校验
    }
}
```
后台使用验证：
```csharp
var validator = new UserValidator();
var result = validator.Validate(user);
if (!result.IsValid)
{
    foreach (var error in result.Errors)
        Console.WriteLine($"{error.PropertyName}: {error.ErrorMessage}");
}
```
**在 WPF 前端结合 IDataErrorInfo：**
- ViewModel 调用 FluentValidation 校验    
- IDataErrorInfo / INotifyDataErrorInfo 将结果暴露给控件显示
**优缺点：**
- **优点**：Model 类非常干净；支持非常复杂的逻辑；易于编写单元测试。    
- **缺点**：需要引入 NuGet 包；需要手动或通过中间件配置集成。
# IDataErrorInfo — WPF/WinForms 经典方案
这是一个早在 .NET 2.0 时代就存在的接口，要求模型实现一个索引器来返回错误信息。
**用在哪些场合：**
- **旧版 WPF 或简单的桌面端项目**。
- 用于 **WPF / WinForms** 的数据绑定时，提供属性级错误信息。
- 纯粹为了让 UI 控件（如 TextBox）变红并显示错误。
- WPF / WinForms 桌面应用    
- MVVM 模式下绑定控件，如 TextBox、ComboBox    
- 必填项、格式检查、小型表单
接口源码：
```csharp
public interface IDataErrorInfo
{
    string Error { get; }               // 全对象错误
    string this[string columnName] { get; }  // 单个属性错误
}
```
模型实现这个接口：
```csharp
public class Student : IDataErrorInfo
{
    public string Name { get; set; }

    // 接口实现
    public string Error => null;
    public string this[string columnName]
    {
        get {
            if (columnName == "Name" && string.IsNullOrEmpty(Name))
                return "名字必填";
            return null;
        }
    }
}
```
XAML 中需设置 `ValidatesOnDataErrors=True`。
```xml
<TextBox Text="{Binding Name, ValidatesOnDataErrors=True, UpdateSourceTrigger=PropertyChanged}"/>
```
优缺点：
- **优点**：WPF 深度集成，兼容性极强。    
- **缺点**：不支持异步（比如检查用户名是否被占用会卡死 UI）；只能一次返回一个错误。
- ⚠ 注意：**它不适合 Web / API / Blazor**，只能桌面 UI 使用。
# INotifyDataErrorInfo — 现代桌面端推荐方案
这是为了取代 `IDataErrorInfo` 而推出的现代接口（.NET 4.5+）。它基于**事件驱动**。
**用在哪些场合：**
- **现代 WPF、MAUI、Avalonia**。    
- WPF / MAUI / Xamarin 桌面和移动应用    
- MVVM 模式    
- 支持多条错误（一个属性可以有多条）    
- 异步校验（如用户名是否重复、外部服务检查）
- 属性错误变化通知 UI
- 需要**异步校验**（如：在后台线程请求 API 验证输入内容）或一个属性有**多个错误提示**。
它不返回字符串，而是触发 `ErrorsChanged` 事件。
接口源码
```csharp
public interface INotifyDataErrorInfo
{
    bool HasErrors { get; }
    event EventHandler<DataErrorsChangedEventArgs> ErrorsChanged;
    IEnumerable GetErrors(string propertyName);
}
```
模型实现这个接口：
```csharp
// 校验逻辑在属性 Setter 中通过代码触发
public class UserViewModel : INotifyDataErrorInfo
{
    private readonly Dictionary<string, List<string>> _errors = new();

    private string _name;
    public string Name
    {
        get => _name;
        set
        {
            _name = value;
            ValidateName();
            OnPropertyChanged(nameof(Name));
        }
    }

	// 校验规则
    private void ValidateName()
    {
        _errors.Remove(nameof(Name));
        if (string.IsNullOrWhiteSpace(Name))
            _errors[nameof(Name)] = new List<string> { "名称必填" };

        ErrorsChanged?.Invoke(this, new DataErrorsChangedEventArgs(nameof(Name)));
    }

    public bool HasErrors => _errors.Any();
    public IEnumerable GetErrors(string propertyName) => _errors.TryGetValue(propertyName, out var errs) ? errs : null;

    public event EventHandler<DataErrorsChangedEventArgs> ErrorsChanged;
}

```
XAML 绑定方式和 IDataErrorInfo 类似：
```xml
<TextBox Text="{Binding Name, UpdateSourceTrigger=PropertyChanged, ValidatesOnNotifyDataErrors=True}" />
```
**优缺点：**
- **优点**：性能好，支持异步，支持多重错误。    
- **缺点**：实现代码比较繁琐（模板化代码多）。
- ⚠ 不适合 Web / API / Blazor。
# 组合使用
## dto 用data annotation, 前台wpf用 IDataErrorInfo
确定结构

| 对象                                                        | 是否适合加 DataAnnotations | 理由                                                 |
| --------------------------------------------------------- | --------------------- | -------------------------------------------------- |
| Domain Entity                                             | ❌ 不推荐                 | Domain 只做核心业务，不关心 UI 校验                            |
| DTO (`ChannelCreateDto`, `ChannelUpdateDto`)              | ✅ 推荐                  | DTO 是跨层传输对象，前端和后端都可以复用校验                           |
| ViewModel (`ChannelAddViewModel`, `ChannelEditViewModel`) | ✅ 推荐                  | 可直接绑定到 UI，实现 IDataErrorInfo 或 INotifyDataErrorInfo |
### 为 DTO 添加 DataAnnotations声明规则
```csharp
using System.ComponentModel.DataAnnotations;

public class ChannelCreateDto
{
    [Required(ErrorMessage = "名称不能为空")]
    [StringLength(50, ErrorMessage = "名称最多50个字符")]
    public string Name { get; set; } = string.Empty;

    [StringLength(200, ErrorMessage = "描述最多200个字符")]
    public string? Description { get; set; }
}
```
- 这样可以在 **WPF ViewModel** 或 **API 服务端**共享验证规则。    
- 对于 `ChannelUpdateDto`，规则可以和 `CreateDto` 类似，也可以单独定义不同的规则。
### WPF > view model 实现 idataerrorinfo触发验证
WPF 中常用的做法：
1. ViewModel 实现 **`INotifyDataErrorInfo`** 或 **`IDataErrorInfo**    
2. 绑定 TextBox 的 `ValidatesOnDataErrors=True`    
3. ViewModel 内部可以调用 DTO 的 DataAnnotations 验证逻辑

写一个基类view model封装dto
```csharp
public abstract class ValidatableViewModel : ObservableObject, IDataErrorInfo
{
    protected abstract object ValidationTarget { get; }

    public string Error => string.Empty;

    public string this[string columnName]
    {
        get
        {
            var context = new ValidationContext(ValidationTarget)
            {
                MemberName = columnName
            };

            var results = new List<ValidationResult>();

            var value = ValidationTarget
                .GetType()
                .GetProperty(columnName)?
                .GetValue(ValidationTarget);

            Validator.TryValidateProperty(value, context, results);

            return results.FirstOrDefault()?.ErrorMessage ?? string.Empty;
        }
    }
}
```
具体 ViewModel 包装 DTO
```csharp
public sealed class UserEditViewModel : ValidatableViewModel
{
    private readonly UserEditDto _dto;

    public UserEditViewModel(UserEditDto dto)
    {
        _dto = dto;
    }

    protected override object ValidationTarget => _dto;

    public string UserName
    {
        get => _dto.UserName;
        set
        {
            _dto.UserName = value;
            OnPropertyChanged();
            OnPropertyChanged(nameof(IsValid));
        }
    }

    public int Age
    {
        get => _dto.Age;
        set
        {
            _dto.Age = value;
            OnPropertyChanged();
            OnPropertyChanged(nameof(IsValid));
        }
    }

    public bool IsValid =>
        !Validator.TryValidateObject(
            _dto,
            new ValidationContext(_dto),
            new List<ValidationResult>(),
            true);
}
```
WPF XAML（零代码-behind）
```xml
<TextBox Text="{Binding UserName,
                        UpdateSourceTrigger=PropertyChanged,
                        ValidatesOnDataErrors=True}" />

<TextBox Text="{Binding Age,
                        UpdateSourceTrigger=PropertyChanged,
                        ValidatesOnDataErrors=True}" />
```
✔ WPF 自动调用 `IDataErrorInfo`  
✔ 自动显示红框  
✔ 支持实时校验
### mvvm.toolkit，wpf > ViewModel 中使用ObservableValidator，推荐
使用 `CommunityToolkit.Mvvm`，**不要再手动实现 `INotifyDataErrorInfo` 了**。 直接让你的 ViewModel 继承 `ObservableValidator`，它已经帮你把最脏最累的事件处理和错误字典管理全部写好了。

```csharp
using System.ComponentModel;
using System.ComponentModel.DataAnnotations;

public partial class ChannelAddViewModel : ObservableValidator // ObservableValidator 是 CommunityToolkit.Mvvm 的辅助类
{
    [ObservableProperty]
    [Required(ErrorMessage = "名称不能为空")]
    [StringLength(50, ErrorMessage = "名称最多50个字符")]
    private string name = string.Empty;

    [ObservableProperty]
    [StringLength(200)]
    private string? description;

    // 其他字段同理

    // 保存命令前验证
    [RelayCommand]
    private async Task Save()
    {
        ValidateAllProperties(); // 验证所有属性
        if (HasErrors) return;   // 如果有错误，不保存

        var dto = new ChannelCreateDto
        {
            Name = this.Name,
            Description = this.Description,
            Direction = this.Direction,
            Style = this.Style,
            TargetAudience = this.TargetAudience
        };

        await _channelService.AddAsync(dto);
        await _navigationService.GoBack();
    }
}
```

```csharp
using CommunityToolkit.Mvvm.ComponentModel;
using CommunityToolkit.Mvvm.Input;
using System;
using System.ComponentModel.DataAnnotations;
using System.Collections.Generic;
using System.Linq;
using System.Threading.Tasks;

public partial class ChannelAddViewModel : ObservableValidator
{
    private readonly IChannelService _channelService;
    private readonly INavigationService _navigationService;

    public ChannelAddViewModel(IChannelService channelService, INavigationService navigationService)
    {
        _channelService = channelService;
        _navigationService = navigationService;
    }

    // 使用 ObservableValidator 的属性
    [ObservableProperty]
    private string name = string.Empty;

    [ObservableProperty]
    private string? description;

    // 保存命令
    [RelayCommand]
    private async Task SaveAsync()
    {
        // 先清空上次错误
        ClearErrors();

        // 创建 DTO
        var dto = new ChannelCreateDto
        {
            Name = this.Name,
            Description = this.Description,
            Direction = this.Direction,
            Style = this.Style,
            TargetAudience = this.TargetAudience
        };

        // 调用 DTO 的 DataAnnotations 验证
        var context = new ValidationContext(dto);
        var results = new List<ValidationResult>();
        bool isValid = Validator.TryValidateObject(dto, context, results, true);

        if (!isValid)
        {
            // 将 DTO 验证结果映射到 ViewModel Errors
            foreach (var result in results)
            {
                foreach (var memberName in result.MemberNames)
                {
                    SetErrors(memberName, new List<string> { result.ErrorMessage ?? "未知错误" });
                }
            }
            return; // 有错误，不保存
        }

        // TODO: 调用服务保存
        await _channelService.AddAsync(dto);

        // TODO: 导航回列表页
        await _navigationService.GoBackAsync();
    }

    // 取消命令
    [RelayCommand]
    private async Task CancelAsync()
    {
        await _navigationService.GoBackAsync();
    }
}
```

## entity(domain)用 fluentvalidation 写规则， 前台wpf用idataerrorinfo
**把校验逻辑写在后台（FluentValidation / Domain 层），WPF 前端只做“错误显示”，通过 IDataErrorInfo / INotifyDataErrorInfo 暴露给控件。**
```csharp
[FluentValidation]  <-- 后台 / Domain 层
      ^
      |
      v
[ViewModel] (IDataErrorInfo / INotifyDataErrorInfo)
      ^
      |
      v
[WPF View] (TextBox / Binding)
```
**特点：**
- 校验逻辑统一在后台（可复用到 Web / Blazor / API）    
- WPF 不需要自己写规则    
- IDataErrorInfo 只做错误暴露和触发 UI 更新    
- 保存 / 提交操作直接调用后台 FluentValidation 校验
- **前端只负责显示** → WPF 用 `IDataErrorInfo` / `INotifyDataErrorInfo` 显示红框和 tooltip
- **易扩展** → 后台规则改了，前端立即生效    
- **保存时可再做一次完整校验** → 安全可靠

```csharp
public class UserModel
```

ViewModel 用 IDataErrorInfo 调用 FluentValidation
```csharp
using System.ComponentModel;
using FluentValidation;
using FluentValidation.Results;

public class UserViewModel : IDataErrorInfo, INotifyPropertyChanged
{
    private readonly UserValidator _validator = new();
    private UserModel _model = new();

    public string Name
    {
        get => _model.Name;
        set
        {
            _model.Name = value;
            OnPropertyChanged(nameof(Name));
        }
    }

    public int Age
    {
        get => _model.Age;
        set
        {
            _model.Age = value;
            OnPropertyChanged(nameof(Age));
        }
    }

    // IDataErrorInfo
    public string this[string columnName]
    {
        get
        {
            ValidationResult result = _validator.Validate(_model);
            var error = result.Errors.FirstOrDefault(e => e.PropertyName == columnName);
            return error?.ErrorMessage;
        }
    }

    public string Error
    {
        get
        {
            ValidationResult result = _validator.Validate(_model);
            if (!result.IsValid)
                return string.Join(Environment.NewLine, result.Errors.Select(e => e.ErrorMessage));
            return null;
        }
    }

    public event PropertyChangedEventHandler PropertyChanged;
    private void OnPropertyChanged(string propertyName)
    {
        PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));
    }
}
```

可优化点（企业级）
- 使用 **INotifyDataErrorInfo** 替代 IDataErrorInfo → 支持异步校验    
- 可以把 **FluentValidation 的 ValidationResult 缓存** → 避免每次属性改变都重新 Validate 整个对象

## 进阶，WPF ViewModel 动态代理 DTO ，只在dto中写一次data annotation
由于 DataAnnotations 是静态特性，C# 无法直接“继承”属性上的特性。我们要么通过 **反射** 手动读取，要么利用 **FluentValidation** 的解耦特性。

| **方案**                  | **维护性** | **实时性**   | **推荐理由**                                    |
| ----------------------- | ------- | --------- | ------------------------------------------- |
| **FluentValidation 组合** | ⭐⭐⭐⭐⭐   | 强         | **最专业**。逻辑完全独立，支持异步，易于测试。                   |
| **反射 SyncAttribute**    | ⭐⭐⭐⭐    | 强         | **最偷懒**。适合已经写了大量 DataAnnotations 的项目。<br>合适 |
| **映射后验证**               | ⭐⭐⭐     | 弱 (点击才验证) | **最简单**。不需要改动 VM 结构。                        |
如果你的项目有“双向同步”和“复杂业务”，请果断选择 **方案一 (FluentValidation)。 因为在同步过程中，你经常需要处理：“如果服务器返回冲突，该如何标记界面上的特定字段？”
这种逻辑 FluentValidation 的 `Failure` 集合处理起来比 DataAnnotations 灵活得多。
### 使用 FluentValidation 实现“单点定义”
这是目前大型项目最推荐的方案。核心思路是：**校验器定义在 DTO 层，ViewModel 内部组合该校验器。**
1. 在 Shared 类库定义校验器
```csharp
public class ChannelValidator : AbstractValidator<IChannelData> // 定义一个接口让 DTO 和 VM 都实现
{
    public ChannelValidator()
    {
        RuleFor(x => x.Name).NotEmpty().Length(2, 50);
        RuleFor(x => x.Direction).NotEmpty();
    }
}
```
在 ViewModel 中集成. 你可以编写一个简单的扩展或基类方法，在 ObservableValidator 触发校验时，调用这个 ChannelValidator。
```csharp
public partial class ChannelAddViewModel : ObservableValidator
{
    private readonly ChannelValidator _validator = new();

    [ObservableProperty] private string name;

    // 当属性改变时，调用 FluentValidation
    protected override void OnPropertyChanged(PropertyChangedEventArgs e)
    {
        base.OnPropertyChanged(e);
        
        // 运行 FluentValidation
        var result = _validator.Validate(this);
        
        // 将 Fluent 的错误同步给 ObservableValidator 的错误字典
        ClearErrors(e.PropertyName);
        var errors = result.Errors.Where(x => x.PropertyName == e.PropertyName);
        foreach (var error in errors)
        {
            AddInternalError(e.PropertyName, error.ErrorMessage);
        }
    }
}
```
在 ViewModel 中简单调用
现在你的 ViewModel 只需要写一行，就能继承 DTO 的所有规则：

### 利用反射，viewmodel自动同步dto的 DataAnnotations
通过反射在运行时把 DTO 上的特性“偷”给 ViewModel。

编写自定义验证特性：`SyncFromDtoAttribute`
这个特性的作用是告诉 ViewModel：去 DTO 里找同名属性的规则。
```csharp
public class SyncFromDtoAttribute : ValidationAttribute
{
    private readonly Type _dtoType;
    public SyncFromDtoAttribute(Type dtoType) => _dtoType = dtoType;

    protected override ValidationResult IsValid(object value, ValidationContext validationContext)
    {
        // 1. 反射获取 DTO 对应属性的特性
        var property = _dtoType.GetProperty(validationContext.MemberName);
        var attributes = property.GetCustomAttributes<ValidationAttribute>();

        // 2. 依次执行 DTO 上的规则
        foreach (var attr in attributes)
        {
            var result = attr.GetValidationResult(value, validationContext);
            if (result != ValidationResult.Success) return result;
        }
        return ValidationResult.Success;
    }
}
```
或
```csharp
[AttributeUsage(AttributeTargets.Property)]
public class SyncFromDtoAttribute : ValidationAttribute
{
    private readonly Type _dtoType;
    private static readonly Dictionary<string, ValidationAttribute[]> Cache = new();

    public SyncFromDtoAttribute(Type dtoType) => _dtoType = dtoType;

    protected override ValidationResult IsValid(object value, ValidationContext validationContext)
    {
        string key = _dtoType.FullName + "." + validationContext.MemberName;

        if (!Cache.TryGetValue(key, out var attributes))
        {
            var prop = _dtoType.GetProperty(validationContext.MemberName);
            attributes = prop?.GetCustomAttributes<ValidationAttribute>().ToArray() ?? Array.Empty<ValidationAttribute>();
            Cache[key] = attributes;
        }

        foreach (var attr in attributes)
        {
            var result = attr.GetValidationResult(value, validationContext);
            if (result != ValidationResult.Success) return result;
        }

        return ValidationResult.Success;
    }
}
```
### 在 ViewModel 内部直接调用 DTO 验证，代码量大
```csharp
using System.ComponentModel.DataAnnotations;

public List<ValidationResult> ValidateDto(object dto)
{
    var context = new ValidationContext(dto);
    var results = new List<ValidationResult>();

    // true 表示递归验证 DTO 内嵌对象
    Validator.TryValidateObject(dto, context, results, validateAllProperties: true);

    return results;
}
```
- `ValidationContext` 提供验证上下文（DTO 实例 + 当前成员名）    
- `Validator.TryValidateObject` 执行 DataAnnotation 校验    
- `results` 收集所有错误
```csharp
public partial class ChannelAddViewModel : ObservableValidator
{
    private ChannelCreateDto _dto = new();

    public string Name
    {
        get => _dto.Name;
        set
        {
            _dto.Name = value;
            ValidateDtoProperty(nameof(Name));
            OnPropertyChanged();
        }
    }

    // 类似方向、风格等属性

    private void ValidateDtoProperty(string propertyName)
    {
        // 1. 验证整个 DTO
        var results = new List<ValidationResult>();
        var context = new ValidationContext(_dto) { MemberName = propertyName };
        Validator.TryValidateProperty(
            _dto.GetType().GetProperty(propertyName)?.GetValue(_dto),
            context,
            results
        );

        // 2. 清空旧错误
        ClearErrors(propertyName);

        // 3. 设置新错误
        foreach (var r in results)
            SetErrors(propertyName, new[] { r.ErrorMessage! });
    }

    public void ValidateAllProperties()
    {
        ClearErrors();
        var context = new ValidationContext(_dto);
        var results = new List<ValidationResult>();
        Validator.TryValidateObject(_dto, context, results, true);

        foreach (var r in results)
        {
            foreach (var member in r.MemberNames)
                SetErrors(member, new[] { r.ErrorMessage! });
        }
    }
}
```


### 使用 AutoMapper 的映射校验
如果你已经在用 AutoMapper，你可以在同步前执行：
```csharp
[RelayCommand]
private async Task Save()
{
    // 1. 先映射为 DTO
    var dto = _mapper.Map<ChannelCreateDto>(this);

    // 2. 验证 DTO (DataAnnotations 静态验证)
    var context = new ValidationContext(dto);
    var results = new List<ValidationResult>();
    
    if (!Validator.TryValidateObject(dto, context, results, true))
    {
        // 3. 将 DTO 的错误反馈回 VM 的 UI
        ClearAllErrors();
        foreach(var error in results) {
            foreach(var memberName in error.MemberNames)
                AddEntityError(memberName, error.ErrorMessage);
        }
        return;
    }
    // ... 执行保存 ...
}
```
